# ميثاق | MITHAQ

منصة عربية للتعارف الجاد بقصد الزواج المعلن أو المسيار، مع احترام الخصوصية ورضا الطرفين وحماية البيانات.

## الحالة التقنية الحالية

هذا المستودع يحتوي على تطبيق ويب فعلي متصل بمشروع Supabase، وليس مجرد نموذج واجهات ثابت. الاستضافة الحالية هي GitHub Pages، وقاعدة البيانات وخدمات Auth وStorage وEdge Functions موجودة في Supabase.

**وجود الخدمات والكود لا يعني أن المنصة اجتازت اختبارات الإطلاق العام.** لا يُعلن عن جاهزية أي ميزة قبل اختبارها من واجهة الموقع وبحسابات اختبار منفصلة.

## المكونات الحالية

- `index.html` — تطبيق الويب العربي المتجاوب.
- Supabase Auth — التسجيل وتسجيل الدخول واستعادة كلمة المرور.
- جداول Supabase — الملفات العامة والخاصة، الرسائل، طلبات الموافقة، والإشعارات.
- Supabase Storage — مخزن خاص لمرفقات المحادثات.
- Edge Function `mithaq-push` — أساس اشتراكات وإرسال إشعارات الويب.
- `manifest.webmanifest` و`sw.js` — أساس تثبيت التطبيق كتطبيق ويب تقدمي (PWA).
- `supabase/migrations/` — سجل ترحيلات قاعدة البيانات.
- `supabase/rollback/` و`supabase/verification/` — ملفات التراجع والتحقق المتاحة لبعض تغييرات قاعدة البيانات.

## وظائف لها أساس برمجي وخلفي

يتضمن المشروع التسجيل والدخول، ملفات الأعضاء، البحث، الرسائل الخاصة، مرفقات المحادثات، إشعارات داخل التطبيق، أساس إشعارات الويب، إجراءات الاهتمام والتجاهل والحظر، البلاغات، ولوحتي الإدارة العامة والمشرف المحدود.

هذه القائمة تصف ما هو موجود في الكود والخلفية، ولا تعني أن كل مسار اجتاز اختباراً شاملاً من واجهة المستخدم.

## نواقص تمنع إعلان الجاهزية للإطلاق العام

- لا يوجد حتى الآن مسار مكتمل للتحقق من الهوية وحفظ مستنداتها بصورة خاصة.
- لا يوجد مخزن وواجهة مكتملان لصور الملفات الشخصية للأعضاء؛ المخزن الموجود مخصص لمرفقات المحادثات.
- بعض صفحات القائمة لا تزال غير مكتملة، ومنها عرض قائمة التجاهل وتوافق الاهتمام والمدونة وقصص النجاح.
- إشعارات الويب تحتاج اختبار إرسال واستلام فعلي على أجهزة ومتصفحات متعددة.
- حماية كلمات المرور المسرّبة في Supabase Auth ما زالت بحاجة إلى تفعيل من إعدادات المشروع.
- يلزم إكمال اختبارات التسجيل وتأكيد البريد واستعادة كلمة المرور والرسائل والإشعارات والملفات وصلاحيات الإدارة من واجهة الموقع.
- يلزم اختبار الوصول من شبكات ومناطق متعددة؛ نجاح اختبار واحد لا يثبت التوفر العالمي.

## قواعد التطوير والإطلاق

1. لا تُحذف بيانات أعضاء ولا تُغيّر إعدادات إنتاج حساسة دون موافقة صريحة وخطة تراجع.
2. تُنفّذ تغييرات التطبيق في فروع مستقلة، وتغييرات قاعدة البيانات عبر migrations قابلة للمراجعة والتراجع.
3. تُراجع سياسات RLS وStorage وجميع دوال `SECURITY DEFINER` قبل الإطلاق.
4. لا يُعرض زر أو قسم على أنه متاح إذا لم تكن وظيفته متصلة بخدمة حقيقية ومختبرة.
5. لا تُستخدم بيانات أعضاء حقيقية لاختبارات الإطلاق؛ تُخصص حسابات اختبار منفصلة عند توفر بيئة مناسبة.
6. لا تُعلن الجاهزية إلا بعد نجاح اختبارات الواجهة والأمن والخصوصية والاستعادة والنسخ الاحتياطي والمراقبة.

**قاعدة المشروع: لا تغيير بلا دليل، ولا اعتماد بلا اختبار، ولا إطلاق قبل الجاهزية.**
