# ميثاق — خارطة التنفيذ

> لا تعني العلامات أو الخطط أن الميزة جاهزة؛ لا تُغلق أي مهمة قبل اختبارها فعلياً.

## المرحلة 1 — الأساس الحالي
- [x] مستودع GitHub وواجهة عربية متجاوبة أولية.
- [x] ربط أولي مع Supabase Auth.
- [x] حفظ الملف الشخصي الأساسي.
- [x] استكشاف أولي للملفات المنشورة.
- [x] طلبات الوصول وقبولها ورفضها (تحتاج اختبارات شاملة).
- [x] مراسلات داخلية أولية بعد قبول الطلب (تحتاج اختبارات شاملة).
- [x] إزالة واتساب من المنتج.
- [ ] توحيد ملفات SQL وترحيلات قاعدة البيانات في المستودع.
- [ ] اختبارات صلاحيات RLS لكل جدول ودالة.

## المرحلة 2 — اكتمال الملف والبحث
- [ ] توسيع الملف بالمواصفات المنظمة المناسبة.
- [ ] تعديل الملف، معاينة ما يظهر للآخرين، وإخفاء/نشر الملف.
- [ ] بحث وفلاتر متعددة وترتيب النتائج.
- [ ] المفضلة وإدارة قائمة المحفوظات.
- [ ] تحسين تجربة الهاتف وإمكانية الوصول.

## المرحلة 3 — التعارف والمراسلات
- [ ] دورة طلب التعارف كاملة: إرسال، إلغاء، قبول، رفض.
- [ ] منع الطلبات المكررة والمتضاربة.
- [ ] صندوق محادثات واضح مع آخر رسالة وتاريخها.
- [ ] تحديث الرسائل وحالة القراءة بصورة موثوقة.
- [ ] ضوابط مكافحة الإساءة ومعدلات الإرسال.

## المرحلة 4 — الثقة والسلامة
- [ ] الحظر ومنع التفاعل المتبادل بعد الحظر.
- [ ] الإبلاغ عن ملف أو رسالة مع سبب وتفاصيل اختيارية.
- [ ] إشعارات داخل التطبيق.
- [ ] إعدادات الخصوصية والتحكم في ظهور الملف.
- [ ] تعطيل الحساب وحذفه وفق سياسة احتفاظ واضحة.
- [ ] لوحة إدارة محمية وصلاحيات منفصلة وسجل تدقيق.

## المرحلة 5 — الجاهزية للإطلاق
- [ ] تحديد الدولة الأولى ومراجعة القوانين المحلية.
- [ ] سياسة خصوصية وشروط استخدام ودعم وشكاوى.
- [ ] اختبار أمني مستقل ومراجعة إعدادات Supabase.
- [ ] اختبار على حسابات متعددة وأجهزة مختلفة.
- [ ] اختبار النسخ الاحتياطي والاستعادة ومراقبة الأعطال.
- [ ] إطلاق محدود بعد إغلاق المخاطر الحرجة فقط.

## قواعد العمل
- واتساب غير موجود في المنتج ولا يُعاد إدخاله.
- لا صور أو فيديو في النسخة الحالية.
- لا بيانات حقيقية في الاختبارات.
- لا نعلن أن الموقع جاهز حتى تكتمل الاختبارات والمراجعات.
