# ميثاق — نظام المحادثات العالمي

> هذه الوثيقة سجل تنفيذ مرحلي وليست إعلانًا بأن كل الميزات جاهزة. التطبيق الأمامي ما زال على فرع منفصل ولم يُدمج في main. أُطبقت ترحيلات قاعدة البيانات الإضافية على مشروع Supabase المشترك بناءً على موافقة المستخدم، مع الحفاظ على البيانات الحالية.

## الهوية الافتراضية المعتمدة للمعاينة
- هوية أصلية خاصة بميثاق، دون نسخ واجهة تطبيق آخر.
- تجربة احترافية شاملة مع سهولة الاستخدام.
- حماية متقدمة مع تحكم واضح للمستخدم.
- العربية والإنجليزية أولًا، مع بنية تسمح بإضافة لغات أخرى.
- RTL وLTR، ووضع فاتح وداكن، وتصميم ملائم للهاتف.

## تدقيق الوضع الحالي

### موجود في التطبيق وقاعدة البيانات
- محادثات مباشرة ورسائل نصية.
- مؤشرات قراءة، وعدّاد رسائل غير مقروءة.
- إشعارات داخل التطبيق وإشعارات Push مُهيأة.
- حالة آخر ظهور تعتمد على تحديث last_seen_at دوريًا.
- مرفقات خاصة في bucket باسم mithaq-chat، وروابط موقعة للعرض.
- دعم عرض الصور والفيديو والصوت والملفات، مع حد رفع حالي 25MB.
- تسجيل الرسائل الصوتية عبر MediaRecorder.
- حذف محلي، وحذف رسائل المرسل للجميع، والحظر، والإبلاغ.
- تفضيلات للمظهر والكتم والمفضلة والاختصار.
- تحديثات Realtime عند فتح المحادثة.

### قيود مؤكدة يجب الحفاظ عليها أو مراجعتها قبل تغييرها
- سياسة قاعدة البيانات الحالية تقيّد الصور والصوت والرسائل الصوتية بالعضوية المميزة؛ لا تُلغى هذه السياسة دون قرار مستقل بشأن التسعير.
- البحث الحالي داخل المحادثة يقتصر على الرسائل المحمّلة، وقائمة المحادثات الحالية تجلب آخر 300 رسالة.
- المفضلة والكتم والاختصار محفوظة كتفضيلات، لكن التكامل الكامل مع كل أجزاء التطبيق لم يكتمل.
- لا توجد في المخطط الحالي بنية مكتملة للردود والتعديل وإعادة التوجيه والتفاعلات وتثبيت الرسائل وأرشفة المحادثات.
- لا توجد بنية مكالمات صوتية أو مرئية مفعّلة.
- لا يوجد تشفير طرفي E2EE مُنفّذ أو متحقق منه؛ الرسائل النصية مخزنة في قاعدة البيانات.
- أظهر فحص Supabase دوال محادثة SECURITY DEFINER قابلة للتنفيذ من anon، ويجب مراجعة صلاحياتها وإغلاق الوصول العام غير المقصود قبل إعلان اكتمال مراجعة الخصوصية.
- بعض تنبيهات الأداء تتعلق بفهرسة مفاتيح أجنبية وسياسات RLS؛ تُراجع مع تغييرات المخطط.

## مراحل التنفيذ

### المرحلة 1 — صندوق المحادثات وتجربة الاستخدام
- [x] إنشاء شريط بحث في قائمة المحادثات.
- [x] إضافة فلاتر الكل، غير المقروءة، والمفضلة اعتمادًا على بيانات موجودة.
- [x] إظهار حالة عدم وجود نتائج ورسائل واضحة.
- [ ] اختبار الفلاتر على حسابين حقيقيين ومحادثات متعددة.
- [ ] إكمال تصميم موحد لقائمة المحادثات ورأس المحادثة والرسائل والملحقات.

ملاحظة: البحث في صندوق المحادثات الحالي يعمل على آخر 300 رسالة المسترجعة، وليس على أرشيف غير محدود.

### المرحلة 2 — محرك الرسائل
- [x] رد واقتباس مع ربط الرسالة الأصلية والتحقق من أن الرسالة الأصلية ضمن المحادثة نفسها.
- [x] تعديل رسائل المرسل خلال 15 دقيقة مع تسجيل وقت التعديل.
- [x] إعادة توجيه النصوص والوسائط بنسخ الملف إلى محادثة المستلم مع حفظ مرجع المصدر.
- [x] تفاعلات Emoji متعددة مع منع التكرار وسياسات RLS.
- [x] تثبيت الرسائل لكل مستخدم على حدة.
- [ ] تحسين التحديد المتعدد والحذف وإظهار حالة كل عملية.
- [ ] ترحيلات إضافية غير مدمرة، مع RLS واختبارات صلاحيات لكل عملية.

### المرحلة 3 — الوسائط والملفات
- [ ] تحسين معاينة الصور والفيديو والملفات قبل الإرسال.
- [ ] إلغاء الرفع وإعادة المحاولة وإظهار تقدم الرفع.
- [ ] التحقق من النوع الفعلي والحجم، وليس امتداد الملف فقط.
- [ ] فحص ملفات آمن وسياسة احتفاظ وتنظيف للملفات اليتيمة.
- [x] تحسين تشغيل الصوت بسرعة 1× و1.5× و2×.
- [x] معاينة الرسالة الصوتية قبل الإرسال وإلغاء التسجيل.
- [ ] عدم تغيير قيد العضوية المميزة قبل قرار منفصل.

### المرحلة 4 — الاتصال الفوري والحضور
- [ ] تحسين مزامنة الرسائل وحالة القراءة عند فتح أكثر من جهاز.
- [x] مؤشر الكتابة اللحظي عبر Supabase Realtime Presence.
- [x] مؤشر استلام منفصل عن القراءة مع صلاحيات RPC مقيدة للمستخدم المصادق.
- [x] تحكم في إظهار آخر ظهور وحالة الاتصال.
- [x] قنوات Presence خاصة، وسياسات RLS تمنع غير طرفي المحادثة من الانضمام.
- [ ] تحديث الإشعارات فورياً مع احترام إعدادات الكتم.
- [ ] قياس استهلاك Realtime والحدود قبل التوسع.

### المرحلة 5 — التنظيم والبحث
- [x] تثبيت المحادثات.
- [x] أرشفة المحادثات وعرضها في فلتر الأرشيف.
- [x] تفضيلات المفضلة والكتم والاختصارات مع إمكانية الإلغاء.
- [x] قوائم المحادثات المثبتة والمؤرشفة مع الاستعادة.
- [x] بحث خادمي في نص الرسائل ضمن المحادثة.
- [ ] بحث خادمي شامل بالاسم والنص والوسائط مع صفحات ونتائج معاينة.

### المرحلة 6 — الخصوصية والأمان
- [x] إعدادات إخفاء آخر ظهور/حالة الاتصال ومؤشرات القراءة والكتابة.
- [x] حفظ حالة القراءة محليًا عبر مؤشر قراءة خاص عندما يخفي العضو إيصالات القراءة عن الطرف الآخر.
- [ ] إدارة الجلسات والأجهزة وتسجيل الخروج من الأجهزة الأخرى.
- [ ] مراجعة كل RPC ذات صلاحيات SECURITY DEFINER وقيود EXECUTE.
- [x] إغلاق EXECUTE من anon/public عن RPCs المحادثة الأساسية، ودوال الحذف والحظر وتسجيل القراءة/الاستلام، مع إبقاء التنفيذ للمستخدم المصادق.
- [ ] تدقيق RLS على الرسائل والمرفقات والبلاغات والتفاعلات.
- [ ] تحديد سياسة الاحتفاظ والحذف والتصدير.
- [ ] مراجعة مستقلة لتصميم التشفير قبل التنفيذ.
- [ ] لا يُعلن E2EE إلا بعد بناء إدارة مفاتيح للأجهزة، وتشفير فعلي من طرف إلى طرف، واختبارات ومراجعة أمنية.

### المرحلة 7 — المكالمات
- [ ] اختيار مزود WebRTC/اتصال مناسب بعد تقييم التكلفة والتوفر في اليمن والخليج.
- [ ] إعداد signaling وتبادل مفاتيح الجلسة والأذونات والإشعارات.
- [ ] بناء واجهة اتصال وارد/صادر وحالات الاتصال والانقطاع.
- [ ] اختبار المكالمات على شبكات ضعيفة وأجهزة متعددة.
- [ ] لا تظهر أزرار اتصال فعالة قبل اكتمال البنية الخلفية.

### المرحلة 8 — اللغات وإمكانية الوصول
- [ ] نقل نصوص المحادثة إلى قاموس ترجمة موحد.
- [ ] العربية والإنجليزية أولًا، ثم إضافة اللغات تدريجيًا.
- [ ] اتجاه تلقائي للنصوص المختلطة RTL/LTR.
- [ ] دعم قارئات الشاشة ولوحة المفاتيح وتباين الألوان.
- [ ] أهداف لمس لا تقل عن 44px وحالات تحميل وخطأ ونجاح واضحة.

## معايير قبول كل مرحلة
1. لا تُضاف أزرار شكلية؛ كل إجراء ظاهر يجب أن ينفذ وظيفة حقيقية أو يبقى مخفيًا حتى يكتمل.
2. لا تُحذف أو تُعدّل بيانات الأعضاء أو الرسائل الحالية.
3. تُختبر صلاحيات المرسل والمستلم ومستخدم ثالث غير مشارك.
4. تُختبر حالات فشل الشبكة، وانتهاء الجلسة، والرفع الجزئي، وتعدد الأجهزة.
5. لا تُستخدم بيانات حقيقية في اختبارات التطوير.
6. لا يُطلب من المستخدم اختبار نسخة جزئية؛ تُعرض معاينة واحدة بعد اكتمال النطاق المتفق عليه، ثم يُنشر إلى main وفق موافقته الصريحة التي منحها للاعتماد النهائي.
7. أُطبقت التغييرات الإضافية الحالية على قاعدة البيانات المشتركة بناءً على تفويض المستخدم، وهي موثقة بملفات migration مطابقة لإصدارات Supabase. أي تغيير إضافي عالي الأثر يحتاج مراجعة مستقلة وخطة تراجع.


## سجل التنفيذ الفعلي — 15 نوفمبر 2026

- أُضيفت إلى قاعدة البيانات حقول الرد والتعديل ومصدر إعادة التوجيه، وحقول تفضيلات تثبيت/أرشفة المحادثة.
- أُنشئت جداول التفاعلات وتثبيت الرسائل مع RLS، وأُغلقت صلاحية anon عن هذه الجداول.
- أُضيف RPC لتعديل رسالة المرسل ضمن نافذة 15 دقيقة مع منع التنفيذ المجهول والتحقق من أن الحساب نشط.
- أُضيفت آليات تحقق من أن الرد يعود إلى نفس المحادثة وأن مصدر إعادة التوجيه متاح للمستخدم.
- رُبطت الواجهة بالرد والتعديل والتوجيه والتفاعلات وتثبيت الرسائل وأرشفة/تثبيت المحادثات والبحث النصي الخادمي.
- أُضيفت معاينة الصوت وإلغاؤها والتحكم بسرعة التشغيل.
- أُضيف حقل delivered_at ودالة آمنة لتسجيل الاستلام، وتعرض الواجهة علامة واحدة للإرسال وعلامتين للاستلام وعلامتين زرقاوين للقراءة.
- أُضيفت إعدادات خصوصية للمستخدم: إخفاء آخر ظهور، إخفاء إيصالات القراءة، وإخفاء مؤشر الكتابة. وعند إخفاء القراءة تُحفظ نقطة قراءة خاصة بالحساب حتى لا يبقى عداد غير المقروء عالقًا، دون كشف read_at للطرف الآخر.
- تم فحص تركيب JavaScript لكل كتل script دون أخطاء نحوية.
- أُغلقت صلاحية anon عن RPCs الخاصة بالمحادثات والحذف والحظر والقراءة والاستلام، وأُنشئت قنوات Presence خاصة بسياسات RLS لا تسمح إلا لطرفي المحادثة النشطين وغير المحظورين. أظهر مستشار الأمان انخفاض دوال SECURITY DEFINER المتاحة لـ anon من 9 إلى 4؛ الأربع المتبقية تخص وظائف اشتراكات/زيارات وليست وظائف المحادثات. فحص البناء لا يعادل اختبارًا حيًا بحسابين أو اختبارًا شاملًا للأجهزة والشبكات.

### ما لا يزال غير مكتمل ولا يُعلن جاهزًا
- اختبار مؤشرات الكتابة والاستلام والقراءة فعليًا بين حسابين وعلى أكثر من جهاز، والبحث الشامل في جميع الوسائط، وإدارة الجلسات والأجهزة.
- استكمال قاموس الترجمة لكل واجهة المحادثة وإعدادات RTL/LTR وإمكانية الوصول.
- اختبارات حقيقية بحسابات مستقلة، واختبار شبكات اليمن والخليج.
- مكالمات الصوت/الفيديو تحتاج signaling وTURN موثوقًا ومراجعة التكلفة والتوفر.
- التشفير الطرفي E2EE غير منفذ؛ لا يجوز وصف النظام بأنه مشفر طرفيًا حتى يكتمل تصميم المفاتيح والأجهزة واختبارات التدقيق.
